# 插件常驻辅助程序：隔离实验结果

整理日期：2026-10-31，Asia/Shanghai。实验实际完成于 2026-10-30 17:57。

## 结论

**能编译、能复用原生同步，但本实验版本不适合直接接入正式插件。**

有社区插件的隔离环境中，常驻调用平均从 CLI 的 2.63 秒降到 1.29 秒，约快
2.04 倍；空插件环境只下降约 6.6%。仍有明显波动，并非稳定的毫秒级操作。

更重要的是，与原生 CLI 同时写入时，已受控复现另一个技能的关联被覆盖。
两个操作都返回成功，也不能证明全部变更被保留。本次结果不支持“直接打包即可
安全达到原生体验”的假设。

正式插件没有切换到辅助程序，Magpie 本体、真实资源库和真实技能状态未被修改。

- 使用官方便携版 Go `1.26.8`，下载 SHA-256 与官方元数据一致。
- 上游源码固定在提交 `0414bbeddbfc2028508b610fd1e7c194143454a0`，License 为 MIT。
- 只在源码副本中新加 `cmd/p21-skills-probe/main.go`，直接调用原生
  `library.SkillAgents()`，没有改写原生同步代码。
- 与原始源码压缩包比较 4,275 个 Go 源码、go.mod、go.sum 和 LICENSE 文件，
  原始文件无变化；哈希见 `source-audit.json`。新增验证包装程序不属于原始文件。
- 可执行文件约 42.4 MiB，构建依赖图为 382 个包，不包含 GUI/Wails 包。
- 通过父进程的 stdin/stdout JSON 行通信，不监听端口，不调用私有 HTTP API。
- 程序只允许固定临时 fixtures 目录内的配置，并拒绝真实/未标记环境。
- Go、源码、编译缓存、依赖和程序都在临时目录；没有系统安装或永久 PATH 修改。

这只是实验程序，不是已经完成生产认证、发布打包和依赖许可证审计的插件组件。

## 对照条件

安装版 CLI 在实验时为 `magpie 0.1.2185`。固定源码提交不保证与该二进制完全一致，
所以额外测试了相同辅助程序的单次进程调用，帮助区分入口与进程复用的影响。

两组数据都只有三个小技能。临时 HOME、Magpie 配置、Agent 目录均独立；
Agent/系统工具使用不读取真实账号的测试替身，WSL 在临时设置中关闭。
社区插件组复制公共包代码和注册名称，不复制登录态、供应商密钥或真实项目。

因此，本次结果不能直接与此前真实环境中 12～20 秒的 CLI 数据相减，也不能据此
承诺实际用户环境的完成时间。数据规模、安装检测、登录态和 WSL 条件均不同。

原生发现返回了 Codex、Claude 和 dsh；测试验证的是包含目标 Agent 且排除 WSL，
不是“恰好只有两个 Agent”。dsh 没有成为本次技能分配目标。

覆盖内容：

- 拒绝真实或未标记的配置目录，拒绝路径形式的技能名。
- 实际调用原生同步启用、关闭技能，并验证 Codex 分发结果。

## 并发覆盖的复现

使用原生已经公开在源码中的 `edit.Filtered()` 作为**仅限实验的暂停点**，没有
修改原生文件或原生事务实现：

1. 辅助程序为 alpha 启用 Codex；原生事务已读取资源库，但暂停在第一次保存前。
2. 安装版原生 CLI 为 beta 启用 Codex，执行结束并返回成功。
3. 此时读取 beta，关联为 `["codex"]`。
4. 放行辅助程序继续保存、同步，它也返回成功。
5. 最终 alpha 为 `["codex"]`，但 beta 变回 `[]`。

原始证据：

```json
{
  "helperOK": true,
  "cliOK": true,
  "betaBeforeRelease": ["codex"],
  "betaAfterRelease": [],
  "alphaAfterRelease": ["codex"]
}
```

原生 `changeLocked()` 的锁是进程内 `sync.Mutex`。辅助程序和原生 CLI 属于两个
进程，不能共享该锁。原生事务读取整个资源库、修改、保存、同步并再次保存；
另一个进程的变化可能被较早的内存副本覆盖，即使两边修改的不是同一个技能。

受控暂停只是确定性安排一个合法的交错顺序，不代表日常操作必然发生或已测得
发生概率。问题在于这个顺序确实能丢失数据，不能以少量普通并发测试无异常来
宣称安全。

这项限制也适用于原生页面与现有插件 CLI 同时写入；退回 CLI 并不自动获得跨
进程原子性。插件自己的队列、文件锁、点击合并或缩短等待都不能单独让原生
进程遵守同一把锁。简单增加插件侧文件锁不是完整修复。
