# 02 - 架构与执行说明

> 更新时间：2026-10-30

## 总体架构

```text
Magpie 插件页 boot.html
        |
        | 读取主题、语言、端口和能力脚本
        v
本地 Skills Management 页面
        |
        | capability + 短期写会话
        v
Bun 本地服务 127.0.0.1:3487
        |
        +-- 读取 library.json / SKILL.md
        +-- 读取 Magpie、Agent 和项目状态
        +-- 保存标签、自定义来源和插件项目元数据
        +-- 调用 magpie CLI 修改全局归属
        +-- 通过受控写入器修改原生项目成员
        +-- 创建和验证 Windows Junction
        +-- 执行固定 Windows 桌面动作
```

Magpie 仍是 Library、技能内容、全局 Agent 归属和原生项目的主要管理者。
本插件提供独立视图和窄范围操作，不替换原生 Library。

## 代码结构

```text
index.mjs                 Magpie 插件入口和本地服务启动
lib/
  service.mjs             HTTP 路由、认证、状态投影和写队列
  cli.mjs                 Magpie CLI 调用
  discovery.mjs           magpie ls 解析和 Agent 发现
  library.mjs             library.json 窄投影和 SKILL.md 描述读取
  metadata.mjs            标签元数据
  features.mjs            自定义来源和插件项目元数据
  projects.mjs            插件项目、Junction 和所有权校验
  native-projects.mjs     原生项目成员受控写入器
  sources.mjs             来源 URL 校验和 GitHub 来源投影
  host-actions.mjs        PowerShell 7 桌面动作调度
  windows-actions.ps1     剪贴板、Explorer、浏览器和目录选择
  avatars.mjs             GitHub 头像有界缓存
  agent-icons.mjs         Agent 图标映射
page/
  boot.html               Magpie 宿主中的启动页
  boot.js                 读取主题、端口和能力脚本
  index.html              本地服务页面
  app.js                  页面状态、渲染和 API 调用
  styles.css              页面样式
  icons/                  Magpie Agent 图标及许可证
test/                     单元、HTTP、启动和隔离视觉测试
docs/                     项目主文档、详细设计、ADR 和历史记录
```

## 启动流程

1. Magpie 根据 `package.json` 的 `magpie.page` 加载 `page/boot.html`。
2. `index.mjs` 启动插件本地服务，默认监听 `127.0.0.1:3487`。
3. 服务生成并持久化页面 capability，同时把端口对应的启动脚本写入 `page/`。
4. `boot.js` 读取 Magpie 主题、语言、端口和 capability。
5. 页面跳转到本地服务地址，capability 只放在 URL fragment 中，随后由
   `history.replaceState` 清除。
6. 页面读取 `/api/state`；写操作先创建短期会话，再携带 capability 和会话头。

如果端口被占用，可以通过 Magpie 的插件 `port` 选项调整。调整端口后，启动脚本
会按新端口重新生成。

## 数据与权威边界

| 数据 | 权威来源 | 插件行为 |
| --- | --- | --- |
| 技能名称、全局归属、原生来源 | Magpie `library.json` | 只做窄投影和受控写入 |
| 技能描述 | Library 下的 `SKILL.md` | 只读取 frontmatter 描述 |
| 原生项目 | Magpie `library.json` | 只读展示；成员菜单走受控写入器 |
| 标签 | 插件 `skills-manager/metadata.json` | 原子写入，保留 `.bak` |
| 自定义来源 | 插件 `skills-manager/features.json` | 校验 HTTP/HTTPS 后保存 |
| 插件项目及链接所有权 | 插件 `skills-manager/features.json` | 只管理插件创建并验证过的 Junction |
| 页面 capability | 插件元数据目录及端口启动脚本 | 不写日志，不进入公开静态路由；Windows ACL 限制为当前用户 |

插件不返回完整 `library.json`，也不把 Magpie 的整个状态对象暴露给页面。

## HTTP 与认证边界

服务只接受回环 Host。业务 API 必须携带 `X-Magpie-Page` capability；写操作还必须
携带短期 `X-Magpie-Session`。服务限制请求体大小、待处理写入数量和会话数量。

主要路由：

| 操作 | 路由 |
| --- | --- |
| 读取状态 | `GET /api/state` |
| 创建写会话 | `POST /api/session` |
| 刷新 Agent 发现 | `POST /api/discovery/refresh` |
| 技能工具动作 | `POST /api/skills/:name/copy`、`folder`、`browse` |
| 设置或清除自定义来源 | `POST /api/skills/:name/source` |
| 全局 Agent 开关 | `POST /api/skills/:name/agents`、`agents/all` |
| 标签 | `POST /api/labels`、`POST /api/skills/:name/labels` |
| 选择项目目录 | `POST /api/projects/choose` |
| 注册插件项目 | `POST /api/projects` |
| 移除插件项目 | `POST /api/projects/:id/remove` |
| 项目 Agent 开关 | `POST /api/projects/:id/skills/:name/agents`、`all` |

不存在任意 Shell、任意路径打开、任意文件写入或任意 URL 抓取接口。

## 写入路径

### 全局 Agent 归属

通过以下 Magpie CLI 修改：

```text
magpie library skill agents <name> <agent-ids|none>
```

写入时优先复用 15 秒内的 Agent 发现结果，读取最新归属，只修改当前可用 Agent，
并保留隐藏/未安装 Agent 的历史关联。发现结果过期时会重新检测；检测失败时不写入。
Magpie CLI 仍校验 Agent，并在写入后重新读取 `library.json` 验证实际结果。

页面会先显示用户想要的开关状态，并用 `aria-busy` 标记写入尚未完成。单 Agent
快速连续点击按技能和 Agent 合并为最终意图；请求进行中再次点击，会在当前请求
返回后补发最终状态。全局开关立即显示目标状态，但等待期间仍禁用同一技能的再次
点击。请求失败时恢复写入前的页面状态并显示错误。

### 原生项目成员

唯一允许直接修改原生项目 `skills` 映射的代码是
`lib/native-projects.mjs`。流程为：

1. 检查 Magpie CLI、项目目录和技能名。
2. 获取进程内写队列之外的独立文件锁。
3. 读取原始 `library.json` 并确认目标项目。
4. 合并当前归属，只修改本次涉及的可用项目 Agent。
5. 保留隐藏、未安装或不支持的项目 Agent 归属。
6. 备份原始文件。
7. 原子替换 `library.json`。
8. 执行 `magpie library sync`。
9. 重新读取并核对项目归属。
10. 任一步失败时恢复原始内容并再次同步。

该路径只允许项目成员菜单使用，不开放原生项目名称、目录或链接的通用编辑。

### 插件项目

插件项目与原生项目相互独立：

- 注册时保存规范化项目根目录和插件项目 ID。
- 目标路径必须位于项目根目录内。
- 目标父目录不能是符号链接或被其他类型占用。
- 只创建指向 Library 技能目录的 Windows Junction。
- 保存 Junction 的目标和身份信息，移除前重新验证。
- 外部目录、冲突链接和原始技能目录不会被覆盖或删除。
- 不使用复制目录作为失败回退。

多个 Agent 可能共享同一个项目技能目录，因此一个 Junction 可能同时服务多个
Agent。页面会提示这种共享可用性，而不是假装每个 Agent 完全隔离。

## 桌面动作

剪贴板、Explorer、默认浏览器和目录选择通过 PowerShell 7 的固定动作脚本执行。
服务只传入已校验的技能名、已知 Library 目录或 HTTP/HTTPS URL，不构造任意命令
字符串。没有必要真实渲染或桌面交互时，不使用 GUI 自动化。

## 本地开发与验证

环境要求：

- Windows
- PowerShell 7
- Bun
- Magpie CLI

命令：

```powershell
Set-Location 'E:\AI-Workspace\mycc\2-Projects\P21-magpie-skills-plugin'
& 'E:\magpie-windows-amd64.exe' --version
bun test
git diff --check
```

隔离视觉服务：

```powershell
bun test/visual-harness.mjs
```

该命令会启动隔离页面服务、临时配置服务和测试项目，不会修改真实 Magpie 项目。
停止后清理临时目录。

推荐验证顺序：

1. `git diff --check`
2. `bun test`
3. 确认 Magpie CLI 版本和插件安装状态
4. 隔离启动、HTTP 和项目生命周期测试
5. 真实 Magpie 页面加载、主题和能力脚本验证
6. 用户可见动作验证：复制、目录、浏览器、项目菜单
7. 只有在明确授权后才执行真实安装或真实项目写入

## 安装与刷新

当前包名：`magpie-skills-manager`  
当前版本：`0.1.0`  
默认端口：`3487`

显式安装或重装：

```powershell
& 'E:\magpie-windows-amd64.exe' plugin add 'E:\AI-Workspace\mycc\2-Projects\P21-magpie-skills-plugin'
```

安装命令不等于完成页面验收。安装后仍需从 Magpie Plugins 入口重新加载页面，
并确认本地服务、能力脚本和实际页面状态。
